# Yashy 1.0.0

This is the 1.0 release note: what the release promises, the numbers the claim
rests on, and — with the same weight — what it explicitly does not promise.
Naming the limits is part of shipping.

## What 1.0 promises

- **The language identity.** No garbage collector, no borrow checker, no
  exceptions, no implicit coercion, no operator overloading, no class
  inheritance, no procedural macros. Ownership is explicit (`move`, `defer`,
  `.free()`); errors are `Option` and `Result` values and `?` propagates them.
- **One object model.** Traits are requirement sets, dispatch is static,
  receivers are `self` or `self: *mut T`, and release is `defer`/`.free()`,
  not a `Drop` trait.
- **One async executor.** `async fn` returns `Task[T]`, `.await` suspends, and
  `scope` joins or cancels its children before it is left. There is no
  pluggable runtime.
- **A verifier that refuses unsound programs.** `yashy build` and `yashy run`
  verify by default; `yashy verify` answers with a proof object — the
  obligation, the missing fact, the remedy — for whatever is missing.
- **Diagnostics as a product.** Every coded diagnostic ends in a `docs:` line,
  `yashy explain <code>` prints the page offline, and `check`, `verify` and
  `test` share one JSON schema (v1).
- **Reproducible, signed releases.** Archives are built from a fixed epoch with
  normalised paths, so two builds of the same tree produce the same bytes;
  every archive ships with `SHA256SUMS` and the signature its platform
  requires (see [release.md](release.md)).
- **Tests are ordinary programs.** A file under `tests/` is a Yashy program
  with a `main`; exit 0 is a pass. No test attributes, no test macros.

## The numbers

Measurements are on the machine described in
[benchmarks/README.md](../benchmarks/README.md) (Windows x86-64,
13th Gen Intel Core i5-13420H, clang 23.1.3); that file carries the methodology
and the full tables.

### Compile time (`fib`, best of 5, ms)

| Toolchain | min | median |
|---|---:|---:|
| Yashy front end only (`--emit-ir`) | 25.4 | 28.3 |
| Yashy full build (`-O2`) | 256.2 | 263.0 |
| `clang -O2` on the same program | 244.8 | 252.4 |
| `go build` | 261.9 | 265.6 |
| `rustc -O` | 558.9 | 600.2 |

A full build is one `clang` invocation — compile the IR and link — and lands
5% above `clang -O2` on the same program; the front end, everything this
repository implements, is 25 ms of the 256.

### Run time (min ms, same programs as the benchmark suite)

| Workload | Yashy | Reference | Ratio |
|---|---:|---|---:|
| `fib(35)` with `wrapping_*` (the opt-out row) | 82.2 | clang 82.0 | 1.00× |
| `fib(35)` checked (the default) | 149.0 | clang 82.0 | 1.82× |
| FFI: 100 M `getpid` calls | 247.8 | clang 237.0 | 1.05× |
| Arrays: 10 M appends | 207.2 | clang 141.1 | 1.47× |
| Maps: 1 M inserts + 1 M lookups | 322.1 | Rust 281.5 | 1.14× |
| Walking a map, 1 M entries | 1065.4 | Rust 567.3 | 1.88× |
| `float`, portable `-O2` | 534.5 | clang 545.6 | 0.98× |

Integer arithmetic is checked by default; the check costs 1.8× on `fib`, where
three checks sit inside a function called thirty million times, and costs
nothing on `loop`, where LLVM proves the loop cannot overflow and deletes it.
`wrapping_*` and friends are the opt-out, and with it Yashy is a tie with
clang inside the noise. See [benchmarks/README.md](../benchmarks/README.md)
for what each row means and what the comparison does not prove.

### Binary size

| Artifact | Size |
|---|---:|
| The `yashy` compiler | 6.4 MB (6585 KB) |
| A release build of `examples/hello` | 263 KB (the budget is < 500 KB) |

There is no runtime library to install: the print helpers are C source
embedded in the compiler binary, and the only external tool is `clang`.

### Test time

- A 100-test project under `yashy test`: **1235 s** for 101 tests
  (measured 2026-11-12, Windows, release build), about 12 s each and
  serially, against a budget of < 2 s. Per-test `--timings` attributes
  0 ms to load, check, verify and emit and 2512 ms to link; the rest is
  host-side per-process cost on that machine (a freshly built program
  binary takes 4 s to launch the first time and 0.05 s on the second,
  `clang --version` takes 1.2 s), so the figure mixes compiler time with
  process-scan overhead and a Linux run may be materially lower. The
  budget is missed either way: open as T3 in [triage](triage.md).
- This repository's own suite (`cargo test --workspace`): **61 minutes**
  (3642 s, measured as the `tests` gate on 2026-11-12).

## The verifier's corpus

| Corpus | Result |
|---|---|
| Seeded bugs (`crates/yashy-driver/tests/verify_corpus`) | 39 programs; every one produces exactly its expected diagnostic codes and exit status |
| Real code (106 programs under `tests/programs` + the 4 example projects) | 110 programs verify clean |
| **False positives on real code** | **zero** — no verifier diagnostic fires on any shipped program |
| Malformed input (`tests/never_panics_corpus`) | 20 files; each produces a diagnostic, never a Rust panic |
| Sandbox escape attempts (`tests/sandbox_corpus`) | 10 attempts; all denied with the right code |

A verifier that reports a bug in working code is worse than no verifier, so
the false-positive count is the headline number: zero, on both operating
systems, enforced by the gate in [gates.md](gates.md).

## Platforms

| Platform | Artifact | Signed how | Tested by |
|---|---|---|---|
| Windows x86-64 (Windows 10+) | `yashy-<v>-x86_64-pc-windows-msvc.zip` | Authenticode with a timestamping authority | install matrix on `windows-latest` |
| Linux x86-64 (glibc 2.35+) | `yashy-<v>-x86_64-unknown-linux-gnu.tar.gz` | GPG signature over `SHA256SUMS` | install matrix on `ubuntu-22.04`, plus install and `doctor` inside a clean `ubuntu:22.04` container |
| macOS, Apple silicon | `yashy-<v>-aarch64-apple-darwin.zip` | Developer ID, notarised and stapled | install matrix on `macos-15` |
| macOS, Intel | `yashy-<v>-x86_64-apple-darwin.zip` | Developer ID, notarised and stapled | built, signed and notarised by the release workflow |

Every release also ships `SHA256SUMS` and both installers (`install.sh`,
`install.ps1`). The install matrix runs from the published artifacts on every
release and weekly afterwards; it installs the Apple silicon archive on
`macos-15` — the Intel archive ships but the matrix does not yet install-test
it, and this page will not pretend otherwise.

Until a signed archive publishes, macOS is tested on every push by CI: the
workspace suite runs on `macos-15`, and the install smoke packages the arm64
archive and drives `install.sh`, `doctor`, the first project and tutorial
chapters 00-02 through it. That archive is unsigned, so it proves macOS builds,
links, runs and installs; it does not make the macOS support claim, which waits
for a signed, notarised archive.

Cross-compilation covers exactly six triples — `x86_64` and `aarch64` for
`pc-windows-msvc`, `unknown-linux-gnu` and `apple-darwin`; any other triple is
`E2200`, which lists the six. A release install needs `clang` and LLVM, and
nothing else: no Rust toolchain.

## What 1.0 does not promise

1. **No dynamic dispatch.** Every trait call names one impl at type-check
   time. There is no `dyn`, no vtable and no runtime type information.
2. **No generic traits.** `Iterator[T]` is the one compiler-known generic
   trait; a user-defined generic trait is `E1511`. Generic functions and
   types monomorphise, capped at 64 instantiations per function and 4096 per
   program (`E1505`).
3. **No async traits.** An `async` trait method is `E1703`. There is no
   `Future` trait and no async closures; one executor is the whole story.
4. **No procedural macros.** Macros are declarative data, expanded before
   parsing in `yashy-expand`, with the caps `E1600`–`E1603`. A macro cannot
   run code at expansion time.
5. **No WASM target.** The six triples above are the whole target set;
   anything else is `E2200`. A browser target is not on the 1.0 path.
6. **No third-party registry hosting.** A registry is a static index —
   `index.json` and one tarball per package — served from a directory or a
   URL. There is no upload API and no service to run: a package reaches a
   registry by a pull request, reviewed by a person
   ([packages.md](packages.md)).
