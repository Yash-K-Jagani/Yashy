# Yashy 2.0 — The Product Language: Design Record

**Status:** proposed 2026-11-15. This record is the design input to the 2.0
master plan; it does not change the compiler by itself.
**Builds on:** [`2026-10-27-yashy-master-design.md`](2026-10-27-yashy-master-design.md).
The 1.0 design remains the authority on the language's identity. This record
adds a release thesis, a surface, and a phase order; it does not reopen the
identity rules in §3 of that document.
**Supersedes:** nothing. The completed 1.0 plan set stays archived under
`docs/superpowers/plans/history/` and is not authoritative.
**Capacity:** one maintainer, full-time.
**Horizon:** 24–30 months, planned at ~138 weeks.
**Companion:** [`2026-11-15-yashy-2.0-master-plan.md`](../plans/2026-11-15-yashy-2.0-master-plan.md).

---

## 1. The thesis

1.0 proved three things:

1. A program can be **provably** safer than C without a garbage collector or a
   borrow checker: ownership, effects, typestate and contracts are checked
   before `clang` runs.
2. A checked language can be **as fast as C** on scalar code, because the
   verifier's facts are spent as deleted checks and IR attributes.
3. A compiler can be **equally legible to a person and an agent**: one fact,
   two renderings, schema v1, a sandbox, and an MCP surface that exposes the
   compiler rather than a shell.

What 1.0 did not prove is that a person can **build and ship a real product**
in Yashy without leaving the language. The loop is still too slow for flow. The
standard library is a documented skeleton. There is no TLS, SQL, serialization,
debugger, package signing, or browser target. The language is missing the trait
and pattern pieces a library ecosystem needs. The agent surface can read code
but cannot safely edit it.

2.0 is the release where Yashy becomes **a place to build**, not a demonstration
that the ideas work.

The five goals, in the order they win when they conflict:

1. **Flow is a must.** A developer or agent should not wait for the compiler.
   Edit-to-diagnostic under 50 ms, incremental builds under 100 ms, 100 tests
   under 2 s. A slow loop taxes every feature added after it.
2. **Product is a must.** A new project must be able to serve HTTP over TLS,
   store data in SQL, parse JSON, run tests, and ship a signed binary using
   first-party packages.
3. **Power is a must.** The language must express systems, services and
   concurrent programs without leaving the 1.0 identity: generic traits,
   associated types, default methods, pattern completeness, threads, atomics,
   SIMD, and a browser target.
4. **Reach is a must.** AI-native is not a chat mode. Agents and people get the
   same facts in two renderings; agents get structured edits, a semantic graph,
   context packs, a sandbox and a benchmark. The compiler reports what it
   proved, what it could not prove, and how to fix it.
5. **Adoption is a consequence.** Install in one command, a registry that can
   be audited, templates, docs, examples, and a 2.0 LTS. Adoption is never a
   reason to cut 1–4.

Trust is not fifth on that list. It is the floor under all five: no feature
ships without its verifier rules, and no performance or safety claim ships
without a number from Windows and Linux.

## 3. Goals and success criteria

| Axis | 2.0 succeeds when |
|---|---|
| **Flow** | Edit-to-diagnostic < 50 ms; incremental build < 100 ms; 100 tests < 2 s; cold `hello` < 1 s; `cargo test --workspace` < 20 min; compile-time regressions caught at 20% with a normalized row |
| **Product** | A new project can serve HTTPS, use SQL, parse and emit JSON, run tests, and ship a signed binary from first-party packages; three production-shaped examples pass on Windows, Linux and macOS |
| **Power** | Generic traits, associated types, default methods and supertraits are static and proven; `let else`, slice/rest patterns, `@` bindings and built-in derives ship with desugar proofs; fixed arrays/const generics, threads/atomics/`RwLock`/`Condvar`/MPMC/`select`/parallel iterators pass their verifier corpus; WASM/WASI runs `hello` in a browser and Node |
| **Reach** | MCP v1 has structured edits and a semantic graph; context packs ≤ 8k tokens; agent benchmark v2 records success, tokens, tool calls, time and sandbox violations; sandbox v1 has default-deny capabilities and resource limits; the Yashy front end bootstraps against the Rust reference with zero mismatches |
| **Trust** | Zero false positives on stdlib, examples, the three production examples and the concurrency corpus; ASan/UBSan/TSan differential clean; every package signed and every binary has an SBOM; reproducible on all claimed platforms; no P0 open |
| **Adoption** | One-command install on Windows, Linux and macOS; `yashyc new` to first test < 1 min; registry round-trip; a 2.0 LTS with a migration path from 1.0 |

## 4. Non-goals (hard)

These are the 1.0 identity rules and they remain out of scope. A 2.0 feature
that needs one of them is not a 2.0 feature.

- No tracing garbage collector. Ownership is linear; strings are
  reference-counted; release is `defer` and `.free()`.
- No borrow checker. Views exist but cannot be named; there are no lifetimes.
- No exceptions. Failure is `Option`, `Result`, a panic, or a process exit.
- No inheritance, no `Drop`, no trait fields, no operator overloading.
- No procedural macros. Macros are declarative data, expanded before parsing.
- No `dyn`, no vtables, no runtime type information, no dynamic dispatch.
  Static dispatch is the object model.
- No async traits, no `Future` trait, no async closures, no pluggable runtime.
- No implicit coercion, no implicit widening, no null.
- No hosted registry service. A registry is a static index plus signed
  tarballs; publishing is a reviewed pull request or an explicit command.
- No macOS support claim until a signed and notarised archive ships.
- No unproven claim. No safety claim without a proof or a test; no speed claim
  without numbers from Windows and Linux.
- No silent scope growth. A new idea goes into the next plan, not the current
  phase.

### 4.1 Anti-goals

- A pile of features with no product story.
- A faster compiler that hides a wrong binary.
- An "AI mode" that is a chat wrapper around a shell.
- A package ecosystem that cannot be audited, pinned, or reproduced offline.
- A 2.0 that breaks 1.0 source. 2.0 is an edition, not a rupture.

## 5. Approaches considered

**A. Feature-first.** Add the language features and libraries now, fix the loop
and the tooling later. Rejected: this is the failure mode 1.0's ordering was
designed to avoid. Every feature added on a 12-second test loop is a feature
nobody iterates on.

**B. Ecosystem-first.** Build the libraries on today's language, then add the
missing trait and pattern pieces. Rejected: a collections or serialization
library built without generic traits, associated types and default methods
either works around them or is rewritten when they land. The stdlib would get
two passes, which is exactly the retrofit tax the 1.0 plan refused.

**C. Flow → language → product → power → reach → release (chosen).** Fix the
loop first, then add the language pieces a library needs, then build the
product stack, then add concurrency, performance, reach, AI-native v2 and
self-hosting, then ship. It preserves the trust ratchet and gives a visible win
each phase.

**D. AI-first.** Build the agent surface before the language and libraries.
Rejected: agents need something worth using. AI-native is a multiplier on a
complete language, not a substitute for one.

## 6. The 2.0 surface

### 6.1 Language

| 1.0 has | 2.0 adds | Gate |
|---|---|---|
| Generic functions/structs/enums, non-generic user traits, `Iterator[T]` special | User generic traits, associated types, default methods, supertraits; `Iterator[T]` remains the compiler-known `for` protocol | Every form has HIR/desugar tests and verifier rules; no `dyn`; monomorphisation cap holds |
| `if let`, `while let`, guards, or/range/nested patterns, named/default args | `let else`, `else if` chains, slice/rest patterns, `@` bindings, `matches`, if-let chains | Every refutable form has an ownership rule; binding position stays irrefutable unless divergent; `else if` adds no HIR |
| `struct`/`enum`/`object`/`impl`; no attributes beyond `repr(C)` and `cfg` | Built-in derives (`Debug`, `Eq`, `Hash`, `Encode`, `Decode`), `repr(packed|align|transparent)`, enums with an explicit integer repr | Derives are compiler-known, deterministic and inspectable; `repr` stays keyword forms |
| Lambdas with inferred capture | Explicit capture modes (`move`, value, by-pointer) and a closure type that names them | Capture mode is in the type; ownership verifier sees every capture |
| `defer { ... }`, `move`, arenas | `defer expr;` form, scoped release helpers, `defer` across suspension points | Release order and async interaction proven; no double free |
| Fixed arrays `[T; N]`, unnamed views | Const generics for array lengths and fixed buffers; named read-only views remain a non-goal | Const evaluation is total; a view cannot outlive its source |
| `const` values and layout facts; no compile-time functions | `const fn` over typed HIR: tables, fixed buffers and validated constants evaluated at compile time, with fuel/depth caps and no I/O, allocation, `unsafe`, `extern` or capability access | Compile-time and run-time values agree; termination is guaranteed; a compile-time-only function is not emitted |
| Unnamed `Mutex`, `Channel`, OS threads | Atomics with orderings, `RwLock`, `Condvar`, `Once`, scoped threads, MPMC channels, `select`, timeouts, cancellation tokens, parallel iterators | Race/typestate corpus; TSan differential; no lock across `.await` |
| `as` casts, bitwise, `repr(C)`, `extern "C"`, `link_name`, variadics | `unsafe { ... }` blocks, ABI strings, `repr` completeness, `bindgen`, `dlopen` | Every unsafe site inventoried; C layout round-trips; bindgen output compiles |
| Typed pointers: owning `*mut T`, FFI `*const T`/`*T`; no null | A written provenance and aliasing model; `noalias` only on `unsafe`/`extern` parameters; `Option[*const T]` as the guaranteed-null FFI form; bounds-checked pointer arithmetic; every emitted `noalias`/`nonnull` explained | Alias corpus; a safe function cannot declare an alias promise it can break; `--opt-report` names the fact behind every attribute |
| `repr(C)` only; layout known to the compiler, not to the user | `repr(packed)`, `repr(align(N))`, `repr(transparent)`, integer enums; `size_of`/`align_of`/`offset_of`; `yashyc inspect --layout`; field reordering for non-`repr(C)` types | Layout report matches the generated IR on every corpus type; C layout round-trips; reordering never changes a `repr(C)` type |
| `alloc(n)` (uninitialised), arenas, values on the stack by default | Zeroed `alloc`; `unsafe alloc_uninit`; an `Allocator` interface; escape analysis that promotes non-escaping constant allocations; explicit `stack_alloc` whose pointer cannot escape; `--alloc-report`/`--stack-report` | No uninitialised read in safe code; every allocation has a reported site; promoted allocations are proven not to escape; no hidden allocation in the runtime |
| No determinism promise | A written determinism contract: defined map/set iteration order, fixed hash seed, capability-gated clock/env/entropy, deterministic scheduler under `--deterministic`, per-target FP promise and `--strict-fp`, no addresses or timestamps in output | The corpus runs twice byte-identically; `--deterministic` at 1 and 4 workers produces the same trace; a program that reads an unfixed capability is reported, not claimed |
| No specification or edition | Language reference, conformance suite, `edition = "2027"`, `yashyc migrate` | 1.0 programs compile unchanged; conformance suite passes on all claimed platforms |

**The one deliberate 1.0 exclusion 2.0 revisits:** user-defined generic traits.
1.0 allows only the compiler-known `Iterator[T]`; 2.0 allows ordinary static
generic traits, monomorphised like generic functions, under the same
monomorphisation cap. This does not add `dyn`, vtables, or async traits. It is
recorded here because it changes `E1511` and the stdlib's trait surface.

### 6.10 Toolchain and platform

1.0's build is one `clang` invocation: it compiles the C runtime that ships with
the compiler, turns the IR into an object and links the binary. That is why
every user needs a C toolchain, why a fresh machine fails before it can print
`hello`, and why the installer, the SBOM and every cross target inherit a
dependency the language does not need.

2.0 makes the default path independent of `clang`:

| Piece | 2.0 arrangement | Gate |
|---|---|---|
| Runtime | The five C sources are compiled once per target into a signed archive, embedded in the compiler or installed with it; `--runtime-source` is a developer path | Archive and source modes export the same symbols and produce the same e2e output; a hash mismatch refuses the build |
| IR to object | `llc` emits per-module objects; `llvm-as` produces bitcode only for LTO | A shim `clang` on `PATH` is never executed |
| Link | `LinkSpec` over `ld.lld`, `lld-link`, Apple `ld` and `link.exe`, with sysroot/CRT discovery and `--linker`/`YASHY_LINKER`/`--sysroot` | Each documented backend links a runnable binary; a missing linker names the missing piece |
| Optimisation | `opt`, `llvm-profdata`, `llvm-cov` and `lld --lto-O2` replace the clang flags for PGO, coverage and ThinLTO | PGO/LTO rows pass without `clang`; a missing stage reports `unavailable` |
| Distribution | A signed toolchain package (`llc`, `lld`, `llvm-ar`/`llvm-lib`, `llvm-as`, `opt`, `llvm-profdata`, `llvm-cov`, Windows `llvm-pdbutil`) pinned to a supported LLVM range; `yashyc toolchain install/list/verify` | Signature and per-file hashes verified; tamper and wrong-triple archives refused |
| Selection | `--toolchain auto/bundled/system/clang`, `YASHY_LLVM`; toolchain identity is in the cache key, SBOM and `--reproducible` output | Two machines with the same package produce the same bytes; a different LLVM is a different build |

`clang` remains supported as a compatibility mode and as the backend for
sanitizers and the TSan differential in CI. It is not a requirement for a
normal build, and `doctor` says which mode it found and what is missing. macOS
keeps the Xcode command-line SDK and Apple `ld`; `ld64.lld` is not a production
linker here, and macOS stays unclaimed until a signed and tested archive ships.

## 8. Why this order

**Flow first** because every later phase is developed, tested and demonstrated on
this loop. The 1.0 test runner misses its own budget by more than 600×; building
three libraries and a concurrency model on that loop would tax every one of
them. Phase 1 also closes the two open performance-process gaps from 1.0: a real
compile-time regression row and interleaved per-pass measurement.

**Language power before the product stack** because the stdlib is the first
consumer of generic traits, associated types and default methods. Building
`Vec`, `Map`, `Set`, serialization and the web framework on non-generic traits
would force the second stdlib rewrite that 1.0's ordering was designed to
avoid. The language phase is also where the ownership verifier gains rules for
the new pattern forms, before libraries depend on them.

**Product before concurrency and performance** because a language with no TLS,
SQL, JSON or test framework is not a product, and optimising a language nobody
can build in is measuring the wrong thing. Product phases are also where the
new libraries get their benchmark rows, so Phase 11 has something real to
optimise.

**Concurrency before performance** because the performance phase's largest
single win — making checked arithmetic vectorisable — is a codegen question
that must coexist with the parallel runtime and the race proofs. Doing
performance first would optimise a runtime that Phase 10 then changes.

**Representation before code generation.** Phase 11 is two slices because they
answer different questions. 11A decides what memory *is*: layout, aliasing
promises, stack promotion, the allocator interface, and the reports that make
each decision inspectable. 11B decides what the compiler *does* with it:
inlining, vectorisation, PGO, LTO and link strategy. Building 11B first would
teach the optimizer to assume a memory model that 11A has not fixed — the
classic miscompile. A pass that cannot name the representation fact it spends
does not land.

**Toolchain independence after code generation.** 11B settles how a release
binary is optimised and linked, and 11C is the slice that does the same work
without a C compiler driver. Doing 11C first would build the pipeline around a
link strategy that 11B is about to change; doing it after reach would repeat
it for every target. It also makes every later install claim true: an archive
that installs a compiler which then asks for Visual Studio Build Tools is not
an install.

**Speed is a standing budget, not one phase.** Every phase carries a benchmark
row and a compile-time row from Phase 1 onward. Phase 11 is where the ceiling
moves furthest, not where speed starts.

**Reach before AI-native** because agents need a semantic graph that includes
the new language forms (traits, associated types, effects, ownership, async)
and the new libraries. Reach is also where a Yashy package consumes a native C
library and where a Yashy library is callable from other languages; both are
ABI facts that must settle before the graph promises an FFI model. MCP v1 is a
rendering of a model that must be complete; building it before Phase 4 would
freeze a model that is about to change.

**Self-hosting and spec last** because both are checks on the whole language.
A Yashy parser cannot agree with the Rust parser on traits and patterns before
those forms exist; a conformance suite cannot be written before the language
stops moving. They are also the two most cuttable phases, and putting them last
keeps the cut cheap.

## 9. Gate protocol

A phase is complete when all six hold on a clean checkout:

1. The phase's gate commands pass on **Windows and Linux**; macOS where the
   phase says so.
2. The phase's demo runs: a copyable command with expected output in the phase
   plan.
3. `cargo test --workspace` is green on both operating systems.
4. No P0 is open; `never_panics`, `sandbox_escape` and `repro-check` are green.
5. The commit hash is recorded in the master plan and the phase plan.
6. The progress ledger at `.superpowers/sdd/<date>-<slice>/progress.md` is
   current.

A missed gate is recorded as a dated **exception** naming the gate, the reason,
the owner and when it will be re-run. Silent slips are not permitted. A phase
with an open exception cannot be marked complete.

Every phase also carries:

- **One experience slice.** A user-visible win, not only infrastructure.
- **One benchmark or measurement row.** No performance claim without a number.
- **One documentation page.** The tutorial, book or reference is updated in the
  same phase.
- **One machine-readable form** for every new verb or diagnostic.

## 10. Cut order and never-cut

When a phase runs long, cut in this order:

playground upgrade → GUI/ML/media packages → Android/iOS/bare-metal targets →
bridges beyond C, Python, Node, Java and .NET (keep the C ABI library) → C++
interop → full self-hosting (keep the front-end differential) → WASM/WASI (keep
the browser proof) → generators/`yield` → const generics beyond fixed arrays →
default methods/supertraits (keep generic traits and associated types) →
HTTP/2 and WebSocket → MySQL/Redis → email/jobs/auth → coverage/bench/fuzz →
REPL → workspaces/features → extra editor plugins → `yashyc task` → sampling
profiler (keep the counter profiler) → `doc --serve` → release channels beyond
stable (keep the signed pointer) → shipping the bundled LLVM toolchain (keep
`llc`/`lld` discovery, the runtime archive and the clean-machine gate) -> BPE
corpus percentage (keep the keyword/operator rule).

**Never cut:**

- The instant feedback loop: test harness v2, incremental build, watch/daemon.
- LSP, debugger and profiler as a set.
- The installed editor and terminal surface: one generated grammar, completions,
  man pages, TTY-aware output and clickable diagnostics.
- The clang-free default path: the runtime archive, `llc`/`lld` linking and the
  clean-machine gate (a system-LLVM fallback is not a substitute).
- Native C libraries as a package: `pkg-config`, vendored sources, the `-sys`
  convention, the curated `libc` and a written safe wrapper.
- The C ABI library surface: `cdylib`/`staticlib`, the generated header and
  versioned symbols.
- Package signing, SBOM, provenance by rebuild, audit and reproducible builds.
- Agent policy, the hash-chained audit log and the approval token.
- The core stdlib: collections, JSON, HTTP/TLS, SQL, CLI, test, log, crypto.
- Generic traits and associated types.
- Concurrency proofs and the TSan differential.
- Checked-arithmetic vectorisation and the per-pass benchmark gate.
- The memory model: typed pointers, the written aliasing rules, layout reporting,
  zeroed allocation, and the stack/heap reports.
- The determinism contract and its differential.
- The traceability matrix, the error catalog and machine-readable diagnostics.
- MCP v1, structured edits, semantic graph, context packs, sandbox v1.
- Both-OS CI, the benchmark gate, and the no-false-positive gate.
- The 2.0 spec, conformance suite and migration path.
- The identity rules in §4.

Cutting any of those does not shrink the release; it withdraws the claim that
Yashy is a product language.

## 11. Risks

| Risk | Mitigation |
|---|---|
| Scope creep across 14 phases | Cut order; quarterly re-plan; one phase at a time; a phase shrinks before it slips |
| Test runner v2 hides a failing test | One harness, but subprocess or fence isolation per test; exit codes, stdout/stderr and expected-failure semantics preserved; the 1.0 test corpus is the differential |
| Build daemon becomes a required service | `serve` is optional; every command works one-shot; daemon is a cache and an event loop, not a second compiler |
| The installed compiler still needs a C toolchain | The runtime is a signed per-target archive; `llc` emits objects and `lld` links; the clean-machine job has no clang, gcc or LLVM to fall back on; a shim `clang` proves the default path never calls it |
| A hand-written linker driver misses what `clang` knew | `LinkSpec` plus sysroot/CRT discovery are tested on every supported distro and VS version; a missing file is named in `E2201`; the `clang` compatibility mode is the differential |
| Editor grammars drift from the lexer | One `GrammarModel` renders TextMate, tree-sitter, Vim and Emacs; generated files are diffed in CI; a new keyword without regeneration fails |
| Terminal output becomes a second implementation | Help, completions and man pages render from one command table; TTY is a rendering; piped output is plain, ordered and stable |
| Incremental cache serves a stale binary | Key covers source, flags, compiler version, target, runtime, features and env; `cache verify`; CI never trusts a foreign cache |
| Structured edits corrupt source | Byte spans plus expected hashes; apply validates before/after; no shell; sandbox default-deny |
| Crypto/TLS homebrew is wrong | Use a vetted C library, not a homegrown primitive; known-answer tests; constant-time tests; security review |
| Semver resolver breaks exact-pin guarantees | Lockfile stays exact; ranges resolve once and are pinned; `--locked` default in CI; `update` is explicit |
| WASM/self-hosting distract from the product | Both are late and cuttable; the browser proof and front-end differential are the minimum kept |
| Performance pass buys one row by selling another | Per-pass gate with interleaved measurements; normalized compile rows; no pass without its own row |
| An alias assumption miscompiles safe code | Owning pointers are unique by linearity; `noalias` is `unsafe`/`extern`-only, so safe code cannot declare a promise it can break; alias corpus on both OSes; every attribute is in `--opt-report` |
| Stack promotion changes observable behaviour | Promotion requires a proven non-escaping, constant-size allocation; the verifier refuses an escaping `stack_alloc`; the whole-program path remains the reference |
| Determinism costs performance | Capabilities are opt-in; the deterministic scheduler is a mode, not the default runtime; every determinism rule has a benchmark row so the cost is a number, not a guess |
| BPE alignment becomes aesthetics | Gate on measurable facts only: every keyword/operator one token in three tokenizers; a corpus percentage; a rejected spelling is recorded with its measurement |
| Layout reordering breaks FFI | `repr(C)` is never reordered; non-`repr(C)` types have no source-level layout promise; the layout report is compared to the IR |
| Agent tooling becomes a shell wrapper | MCP exposes compiler verbs only; no arbitrary process; sandbox escape corpus in CI |
| A native C library works only on the build machine | pkg-config/sysroot are target-qualified; resolved paths and hashes are recorded; cross use of a host library is refused; `build.ya` is sandboxed and deterministic |
| A bridge frees the wrong allocator or leaks | Copy/transfer is explicit in the generated signature; both-allocator tests; no panic or exception across C; the host matrix is generated from tests |
| An agent exceeds its mandate | Policy file with a strict default, sandbox, budgets, approval token bound to tree+patch+verbs, hash-chained audit log, untrusted-text labelling |
| A release channel or advisory feed is spoofed | Signed immutable archives and a signed versioned advisory feed; a channel is a pointer; verification fails closed |
| Identity drift | The non-goals in §4 are hard; an RFC is required to revisit one; the spec and conformance suite pin the language |
| Maintainer burnout | Visible win each phase; phases shrink; cut list is explicit; quarterly re-plan |

## 12. Governance: editions, RFCs, LTS

- **2.0 is an edition, not a break.** `yashy.toml` gains `edition = "2027"`.
  A 1.0 project builds unchanged under the default edition; `yashyc migrate`
  rewrites it to the 2027 edition and reports every semantic change. The 1.0
  compiler remains able to build 1.0 editions for the LTS window.
- **RFC process.** A language change needs a short RFC: motivation, syntax,
  HIR, verifier rules, diagnostics, migration, benchmark/doc impact, and a
  written decision. The 2.0 design is the first RFC-sized record; later changes
  are smaller.
- **Spec and conformance.** The language reference is versioned with the
  compiler. A conformance suite runs on every claimed platform; a feature is
  not shipped until its conformance cases pass.
- **The architecture document is normative.** `docs/architecture.md` states the
  pipeline, the memory and aliasing model, the determinism contract and the
  traceability rules. A change that makes a sentence false updates the sentence
  in the same commit; Phase 2 adds its drift test.
- **Determinism is a compatibility promise.** A change that makes a
  deterministic program non-deterministic is a breaking change, not a bug fix.
  It needs an RFC and a migration note.
- **Traceability is generated.** Rules, diagnostic codes, conformance cases and
  stdlib coverage are one matrix emitted by `yashyc trace`; hand-maintained
  duplication is a defect.
- **Deprecation policy.** A deprecation warns for at least one minor release,
  carries a code and a `yashyc fix`, and is removed only in an edition.
- **LTS.** 1.0 gets security and critical fixes for 18 months after 2.0. 2.0 is
  the new LTS baseline.
- **Quarterly re-plan.** Dates and the cut list may change; the identity, the
  non-goals and the never-cut list may not. No silent scope growth.

## 13. Definition of done

2.0 is done when:

1. All fourteen phase gates (sixteen slices) pass on Windows and Linux, and the
   phases that claim macOS pass there too.
2. Every language construct has verifier rules, a conformance case and a rule
   ID in the traceability matrix.
3. A new project can serve HTTPS, use SQL, parse JSON, run tests, and ship a
   signed binary from first-party packages.
4. 100 tests run in under 2 s; incremental builds in under 100 ms;
   edit-to-diagnostic in under 50 ms.
5. Checked `fib` is under 1.5× C; `loop` at `--cpu=x86-64-v3` is under 1.2×
   wrapping; every feature row is under 1.8×.
6. The memory model is written and enforced: typed pointers with provenance,
   the documented aliasing rules, a layout report that matches the IR, zeroed
   allocation, and stack/heap reports for every promoted or heap-served
   allocation.
7. The determinism contract holds on the corpus: two runs produce identical
   bytes and traces; `--deterministic` at 1 and 4 workers agrees; every
   capability a program reads is named.
8. MCP v1, the semantic graph, context packs, structured edits, semantic review
   and impact, `yashy-sdk`, agent policy/audit/approval, agent benchmark v2 and
   sandbox v1 pass their gates; no sandbox escape; the BPE gate passes.
9. A package consumes a native C library through pkg-config or vendored source
   with a generated `-sys` package and a tested safe wrapper; a Yashy library is
   callable from C, C++, Python, Node, Java, .NET, Go, Ruby, Swift, PHP, Lua and
   R through generated bridges; no host is claimed on a build alone.
10. The Yashy front end bootstraps against the Rust reference with zero
    mismatches; the language reference and conformance suite are published; the
    architecture document is current.
11. The release is signed, reproducible, install-tested on all three OSes, and
    has an SBOM and provenance; channels are signed pointers, the advisory feed
    verifies and the benchmark dashboard has history; a machine with no `clang`,
    C compiler or LLVM builds, tests, debugs and reproduces from the installed
    archive; no P0 is open.
12. 1.0 projects compile unchanged, and `yashyc migrate` upgrades them.

## 14. Open decisions recorded as calls

These are calls this record makes so the plan can be written; they are the
first things to revisit if the owner disagrees.

1. **Identity is unchanged.** All §4 non-goals stay. A feature that needs one
   is deferred to a later design, not smuggled into 2.0.
2. **Flow comes before product.** The test loop is fixed before libraries are
   built on it.
3. **Language power comes before the product stack.** The stdlib uses generic
   traits, associated types and default methods; it is not rewritten twice.
4. **Build daemon is optional.** One-shot commands remain the contract; the
   daemon is a performance and event-loop layer.
5. **Registry stays static and signed.** No hosted service; packages are
   tarballs plus a signed index plus an SBOM.
6. **Crypto and TLS use a vetted C library.** No homegrown primitives; the
   package wraps a known implementation and tests against published vectors.
7. **Self-hosting targets the front end.** The Rust parser stays the reference;
   the Yashy front end is a differential and a bootstrap, not a second source
   of truth in the first release.
8. **WASM is late and cuttable.** It is a reach goal, not a 2.0 release
   blocker.
9. **macOS is claimed only when signed.** The 1.0 rule stands.
10. **No new compiler runtime dependency without a plan.** C libraries used by
    packages are package dependencies, pinned and audited, not compiler
    dependencies.
11. **Determinism is a contract, not a mode.** Defined iteration order, zeroed
    allocation and capability-gated clock/env/entropy are always on. The
    deterministic scheduler is opt-in because threads exist; the claim names
    the capabilities it fixed.
12. **No source-level `inline` keyword.** Inlining is a pass with a measured
    policy and `--opt-report`, not an annotation a user can use to win one
    benchmark.
13. **Type-safe pointers without a borrow checker.** `*mut T` stays the linear
    owner; `*const T`/`*T` stay the FFI edge; provenance, bounds and the
    non-null niche for `Option[*const T]` are compiler facts. No lifetimes, no
    `&mut`, no aliasing model that assumes a checker the language does not have.
14. **BPE alignment is measured, never aesthetic.** Keywords and operators must
    be one token; the corpus percentage is a gate; a spelling is rejected only
    with a recorded measurement.
15. **`docs/architecture.md` is normative.** It is the one place that states the
    pipeline, the memory/aliasing model, the determinism contract and the
    traceability rules. It is updated with the code, and Phase 2 adds a drift
    test.
16. **`clang` is optional.** The default build uses a signed runtime archive,
    `llc` and `lld`; `clang` remains a compatibility and sanitizer backend.
    The compiler ships a pinned toolchain package or accepts a system LLVM in
    a supported range; neither is guessed.
17. **The editor and the terminal are product surface.** VS Code and Neovim are
    the gated pair; Helix, Zed, Emacs and JetBrains are documented and cuttable.
    One grammar model renders every editor, and one command table renders help,
    completions and man pages.
18. **The toolchain is a build input.** Its mode, version and file hashes are in
    the cache key, the SBOM and `--reproducible` output. A different LLVM is a
    different build, not a silent variable.
