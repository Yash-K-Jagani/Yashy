# E1405 — uninitialised allocation outside unsafe

`alloc_uninit(n)` was written outside an `unsafe` block.

## Cause

Safe `alloc(n)` zeroes every byte it hands out: a program that reads what it
wrote prints the same bytes on every run. `alloc_uninit(n)` deliberately skips
the zeroing, so a read before a write can expose whatever the allocator left
behind. That breaks rule **DET-4** (output is byte-stable) unless the program
takes responsibility for it. The `unsafe { }` block is that responsibility, in
one place a reader and `verify --inventory` can find.

There is no safe spelling for uninitialised memory. `""` and `0` are values a
program can produce, so a zeroed allocation cannot be used as a failure
sentinel; `alloc_uninit` is an opt-out, not a different success value.

## Example

```text
$ yashyc check uninit.ya
error[E1405]: `alloc_uninit` requires an `unsafe` block
  --> uninit.ya:2:18
   |
 2 |     const p = alloc_uninit(4);
   |               ^^^^^^^^^^^^^^
   |
   docs: https://yashy.dev/errors/E1405
```

## Fix

Write the allocation inside an `unsafe` block and initialise every byte before
reading it:

```text
unsafe { p = alloc_uninit(4); }
p[0] = 1;
```

If the program does not need to skip the zeroing, use `alloc(4)`: it is safe,
zeroed, and eligible for escape analysis just as before.
