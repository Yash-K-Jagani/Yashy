# E2203 — cfg in the wrong place

`cfg(..)` guards exactly three positions:

- an **item**: `cfg(windows) import win;`, `cfg(unix) pub fn spawn() { .. }`
- a **statement block**: `cfg(unix) { let socket = ...; }`
- a **struct field**: `cfg(windows) handle: u64,`

Anywhere else it has nothing to delete, so the parser reports it rather than
accepting a condition that does nothing.

## Cause

The filter that acts on `cfg` runs on the AST before name resolution:
removing an item, a statement or a field is a structural edit. An expression, a
parameter or a `let` has no structural slot to remove, and a condition around
one would suggest a guarantee the compiler does not make — an expression is
still evaluated, and a `let` still binds.

## Example

```yashy
fn main() {
    let int x = cfg(windows) 1;
}
```

```text
cfg_on_let.ya:2:17
error[E2203]: `cfg` guards an item, a statement block or a struct field, not an expression
    let int x = cfg(windows) 1;
                ^^^
  docs: https://yashy.dev/errors/E2203
```

## Fix

Guard the block, and keep the binding inside it:

```yashy
fn main() {
    cfg(windows) {
        print("Windows");
    }
}
```
