# E1003 — arena value escapes its block

A value allocated inside an `arena { }` block is returned, stored in an outer
binding, or handed to a thread.

## Cause

`arena { }` frees every allocation written inside the block when the block
ends, on every exit path. A pointer that leaves the block therefore dangles:
the block has already released the memory the pointer names.

The verifier checks this before the program runs. `E1003` is reported when an
arena-owned value is:

- returned from the function,
- assigned to a binding declared outside the block,
- stored in a struct field, a slice element, or an aggregate that can
  outlive the block,
- handed to `thread_spawn`, which keeps it alive on another thread.

A plain call argument is not an escape. A callee may read and write the memory
while the block is live; ownership does not move.

## Example

```yashy
fn make() -> *mut int {
    arena {
        let buf = alloc(16);
        return buf;
    }
}
```

```text
make.ya:4:17
error[E1003]: arena value `buf` is used after its `arena { }` block ends
    return buf;
    ^^^^^^^^^^
  docs: https://yashy.dev/errors/E1003
```

## Fix

Keep the value inside the block, or allocate it outside the block.

```yashy
fn use_it() -> int {
    arena {
        let buf = alloc(16);
        buf[0] = 7;
        return buf[0];
    }
}

fn make(n: int) -> *mut int {
    let buf = alloc(n);
    return buf;
}
```

The first function returns a number, not the pointer, so it stays inside the
block. The second allocates outside any arena, so the caller owns the result.
