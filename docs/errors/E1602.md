# E1602 — macro metavariable kind mismatch

A metavariable is malformed, or it names a fragment kind the supplied input is
not a fragment of.

## Cause

The fragment kinds in v1 are exactly `expr`, `stmt`, `pat`, `ty`, `ident`,
`block`, and `item`. There is deliberately no `tt` kind: a metavariable that
can be anything is one the checker cannot re-parse deterministically. The
input is re-parsed with the parser's own entry point for the kind the
metavariable names, so an expression given to `$name:ty`, or a type given to
`$name:expr`, is rejected at the invocation rather than explained later as a
type error in generated code.

## Example

```yashy
macro get { $value:ty => { $value } }
fn main() { let n = get(1 + 2); }
```

```text
main.ya:2:18
error[E1602]: `$value` is a `ty` fragment, and `1 + 2` is not a type
fn main() { let n = get(1 + 2); }
                  ^^^
  docs: https://yashy.dev/errors/E1602
```

## Fix

Move the metavariable to the fragment kind the input actually is, or fix the
call to supply that kind. If the shape is useful but this kind is too narrow,
split the arm rather than widening the kind.
