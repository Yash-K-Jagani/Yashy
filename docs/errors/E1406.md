# E1406 — FFI pointer dereference outside unsafe

A C pointer was read or written outside an `unsafe` block.

## Cause

An owning pointer (`*mut T`) is linear, so Yashy knows there is exactly one path
to its allocation. A pointer that came from C (`*const T` or a bare `*T` in an
`extern` declaration) carries no such promise: C may keep another pointer to the
same bytes, free them on another thread, or hand back an address that was never
valid. Rule **ALIAS-2** says FFI pointers may alias and that no uniqueness
assumption crosses the boundary on its own. Reading `p[0]` is where that
assumption would be made, so the language asks for `unsafe` there.

This is not a ban on C pointers. It is one place for the reader, the reviewer
and `yashyc verify --inventory` to see where the program took responsibility.

## Example

```text
$ yashyc check ffi.ya
error[E1406]: dereferencing a C pointer requires an `unsafe` block
  --> ffi.ya:3:18
   |
 3 |     const first = p[0];
   |                   ^^^
   |
   docs: https://yashy.dev/errors/E1406
```

## Fix

Put the access in an `unsafe` block and keep the C side of the promise:

```text
fn main() {
    let p = malloc();
    unsafe { print(p[0]); }
}
```

Owning pointers are unaffected: `let p = alloc(4); print(p[0]);` is still safe
and still zeroed.
