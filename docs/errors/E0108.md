# E0108 — `offsetof` needs a `repr(C)` struct and a known field

`offsetof(T, f)` reports where the field `f` starts inside a value of type
`T`. Both halves have to be answerable: `T` must be a struct whose layout is
C's, and `f` must be one of its fields.

## Cause

A field's offset is only a fact about the program when the layout is fixed by
a rule the program can name. Yashy's own struct layout is the compiler's
business and may change; a `repr(C)` struct's layout is the C ABI's, which is
why `offsetof` accepts only that.

The three ways to get this code:

- `T` is a struct without `repr(C)`;
- `T` is not a struct at all — an `enum`, a primitive, an array;
- `f` is not a field of `T`. The note lists the fields `T` does have.

## Example

```yashy
struct Point {
    x: f64,
    y: f64,
}

fn main() {
    print(offsetof(Point, y));
}
```

```text
offset.ya:7:11
error[E0108]: `offsetof` needs a `repr(C)` struct: `Point` has Yashy's own layout
    print(offsetof(Point, y));
          ^^^^^^^^^^^^^^^^^^
  note: add `repr(C)` in front of `struct Point` to fix its layout
  docs: https://yashy.dev/errors/E0108
```

## Fix

Mark the type `repr(C)` when the offset is part of an ABI you are matching.
The offset of an unknown field is reported with the field list, so a typo is
easy to see.

```yashy
repr(C) struct Point {
    x: f64,
    y: f64,
}

fn main() {
    print(offsetof(Point, y));
}
```
