# E0301 — mixed `?`

`?` propagates one kind of failure: `None` for an `Option`, `Err` for a
`Result`. The function around it must be able to return that same kind, so the
two do not mix.

## Cause

`?` is a return in disguise. Applied to an `Option`, it means "on `None`,
return `None` from here"; applied to a `Result`, it means "on `Err`, return that
error from here". The enclosing function therefore decides which subject types
are legal:

- an `Option` subject needs a function returning `Option`;
- a `Result` subject needs a function returning `Result`;
- a function returning anything else can carry neither.

Using an `Option` inside a `Result` function (or the other way round) is the
mistake this code names. A function that returns neither is the same mistake
with no failure channel at all.

## Example

```yashy
fn first(Option[int] o) -> Result[int, string] {
    const int v = o?;
    return Ok(v);
}
```

```text

error[E0301]: `?` on an `Option` needs a function returning `Option`
    const int v = o?;
                  ^^
note: this function returns `Result[int, string]`: use `switch` to handle the `Option`, or change the return type
  docs: https://yashy.dev/errors/E0301
```

## Fix

Handle the value where the kinds differ, instead of propagating it:

```yashy
fn first(Option[int] o) -> Result[int, string] {
    switch o {
        case Some(v) { return Ok(v); }
        case None { return Err("missing"); }
    }
}
```

The other fix is to make the signatures agree: return `Option[int]` from the
function and let `?` propagate `None`, or change the subject to a `Result`.
Whichever way it goes, one function has one failure channel.

`?` on a value that is neither an `Option` nor a `Result` is a separate
diagnostic: there is no failure to propagate at all.
