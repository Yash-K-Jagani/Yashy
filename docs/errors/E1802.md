# E1802 — lockfile mismatch

`yashy.lock` and `yashy.toml` disagree, or the lockfile is not the file the
format describes.

## Cause

A lockfile is the build: it names every package, its exact version, its source
and a content hash of its tree. Resolution never quietly re-resolves a
mismatch, because that is how a build becomes unreproducible without anyone
noticing. `yashy lock --check` and `yashy build` compare the two files and
report the package that differs.

The same code covers a malformed lockfile — a field the format does not have, a
hash that is not `sha256:` plus 64 hexadecimal digits, a package listed twice,
or a version that is not an exact pin.

## Example

```text
error[E1802]: the manifest requires `http` 0.3.2, but yashy.lock pins 0.3.1; run `yashy update`
  docs: https://yashy.dev/errors/E1802
```

## Fix

Run `yashy update` after an intentional manifest change, and commit the new
`yashy.lock` with it. If the lockfile was hand-edited, restore it from version
control instead: the content hash must describe the source tree that is
actually built. See [E1800](E1800.md) for a manifest that will not parse at
all.
