# E1702 — resource held across an await

A locked mutex, or a linear resource with no `defer` release, must not be live
at an `await`.

## Cause

`await` suspends the task and the executor may run another task before this one
resumes. A mutex held across that suspension is held while the task is not
running, so a second task that needs the same mutex blocks behind a lock whose
owner is not even on a thread; on a single-threaded executor that is a
deadlock, not a style issue. A linear resource held across the suspension has
the same shape: it is live while the task can be cancelled, and cancellation
must release it, which only a `defer` arranges.

## Example

```yashy
async fn g() -> int { return 1; }

async fn f() -> int {
    let m = mutex_new();
    m.lock();
    let n = g().await;
    m.unlock();
    return n;
}
```

```text
main.ya:6:16
error[E1702]: mutex `m` is held across an `await`
    m.lock();
    ^^^^^^^^
  docs: https://yashy.dev/errors/E1702
```

## Fix

Release before suspending, or defer the release so it runs on every path,
including cancellation:

```yashy
async fn f() -> int {
    let m = mutex_new();
    m.lock();
    defer { m.unlock(); }
    let n = g().await;
    return n;
}
```
