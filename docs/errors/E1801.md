# E1801 — dependency cycle

Package dependencies form a cycle, so there is no order in which to build them.

## Cause

Packages are compiled from source in dependency order: a package's dependencies
are ready before the package itself. A cycle has no first package, and Yashy has
no module-level initialization order or forward declaration that could give one
a meaning. The resolver refuses the graph before it reads any source, and prints
the cycle it followed.

This is a package cycle (`a` needs `b`, `b` needs `a`), not an import cycle
inside one program; that is [E0802](E0802.md).

## Example

```text
error[E1801]: dependency cycle: a -> b -> a
  docs: https://yashy.dev/errors/E1801
```

## Fix

Break the cycle in the manifests. A shared type can live in a third package
that both depend on; if the two really are one unit, merge them into one
package. Running `yashy update` after the edit rewrites the lockfile.
