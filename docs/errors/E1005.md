# E1005 — owning pointer copied without move

An owning pointer was copied from a binding instead of being moved.

## Cause

An owning pointer is unique: exactly one binding owns the allocation. Passing a
bare name to a new binding would copy the pointer bits and leave two owners,
each of which would release the same allocation. Rule **ALIAS-1** is what makes
the backend's `noalias` and `nonnull` attributes sound: a pointer parameter
passed by value is the only path to its allocation for the duration of the call.
A copy would break that promise, so the checker refuses it and suggests the
explicit transfer.

## Example

```yashy
fn main() {
    let p = alloc(8);
    const q = p;
    q.free();
    p.free();
}
```

```text
main.ya:3:15
error[E1005]: cannot assign linear value `p` without `move`
    const q = p;
              ^
  docs: https://yashy.dev/errors/E1005
```

## Fix

Say the transfer out loud, and do not use the old name afterwards:

```yashy
const q = move p;
q.free();
```

A function parameter of pointer type takes ownership the same way: a bare name
is moved into the call, while `move` is accepted when the intent helps a reader.
FFI pointers (`*const T` and bare `*T`) are different: they may alias and are
linearity-exempt.
