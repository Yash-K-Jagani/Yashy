# E1703 — async method in a trait

A trait method may not be `async`.

## Cause

This is a written cap of the language, not an oversight: there is no
`async` trait. A trait is a requirement set with static dispatch and no
state, and an `async fn` returns a `Task[T]` rather than its result, so a
trait method that was `async` would need a task type at its dispatch site,
and the trait would have to say which executor drives it. The language
answers with one executor and synchronous traits instead.

An `impl` therefore cannot satisfy an async trait method either, because
the trait does not declare one.

## Example

```yashy
trait Worker {
    async fn run(self);
}
```

```text
main.ya:2:5
error[E1703]: `run` is an async method of trait `Worker`: traits have no async methods
trait Worker {
    async fn run(self);
    ^^^^^^^^^^^^^^
  docs: https://yashy.dev/errors/E1703
```

## Fix

Declare the synchronous method, and make the implementation `async` only
where the language allows it — on a free function or an inherent
`impl` method:

```yashy
trait Worker {
    fn run(self);
}
```
