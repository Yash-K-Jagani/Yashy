# E1809 — registry index mismatch

The registry index does not name the package being verified, or names a
different hash for it.

## Cause

`yashyc verify-package --registry <dir>` compares the tarball against the
registry's `index.json`. The index records the tree hash of each published
package, so a tarball whose contents hash to something the index never published
is not the package the registry claims. A stale index, a hand-edited tarball, or
a package that was never published all look like this.

## Example

```text
yashyc verify-package --registry ./registry demo-1.0.0.tar.gz
{"findings":[{"code":"E1809","detail":"no registry entry has hash sha256:..."}]}
```

## Fix

Publish the package (`yashyc publish --registry <dir> --key-id <id>`) so the
index names its hash, or verify the tarball against the registry that published
it. A tarball that does not match any published hash should not be installed.
