# E0802 — import cycle

Modules import each other in a circle: `a` imports `b`, and `b` (directly or
through other modules) imports `a` again. Yashy has no forward declarations
and no module-initialization order, so there is nothing a cycle could mean —
the loader refuses it instead of looping.

## Cause

The loader walks the import graph depth-first. When it reaches a module that
is already on the discovery stack — still loading, not yet loaded — the
import that closes the loop is reported, with the whole cycle written out.
The diagnostic carries `E0802` and points at the import statement that
closes it.

## Example

```yashy
// a.ya
import b;
pub fn a() -> int { return b(); }
```

```yashy
// b.ya
import a;
pub fn b() -> int { return 1; }
```

```text
b.ya:1:1
error[E0802]: import cycle: a.ya -> b.ya -> a.ya
import a;
^^^^^^^^
  docs: https://yashy.dev/errors/E0802
```

## Fix

Break the cycle: move the shared declarations both modules need into a third
module that neither of them imports back, and import that from each. Yashy
does not allow two modules to depend on each other, even when the dependency
is only declarations.
