# E1504 — ambiguous method

Two trait impls for one type provide the same method name, so a call on a
value of that type has two equally good targets. Static dispatch has no way
to choose between them, and import order is not a rule.

## Cause

Resolution runs in a fixed order — inherent impl first, then the trait
impls in scope, then a bound. Two candidates at the SAME level are not
resolved by order: they are refused with `E1504` naming both traits. An
inherent method always wins silently; only same-level ambiguity is an error.

## Example

```yashy
trait Show { fn show(self) -> string; }
trait Debug2 { fn show(self) -> string; }
struct Point { x: int }
impl Show for Point { fn show(self) -> string { return "s"; } }
impl Debug2 for Point { fn show(self) -> string { return "d"; } }

fn f(Point p) -> string { return p.show(); }
```

```text
main.ya:7:29
error[E1504]: `show` is ambiguous on `Point`: both `Debug2` and `Show`
provide it (qualify with `Debug2::show(x)` or `Show::show(x)` once `::`
is available)
fn f(Point p) -> string { return p.show(); }
                            ^^^^
  docs: https://yashy.dev/errors/E1504
```

## Fix

Rename one of the methods so the two traits do not collide, or remove one
of the impls. Once `::` type paths exist, qualify the call with the trait
whose method is meant.
