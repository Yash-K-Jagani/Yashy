# E1511 — generic trait outside the standard library

Type parameters on a trait are a reserved spelling. In 1.0 the only generic
trait is the standard library's `Iterator[T]`, declared in `iter.ya`;
writing one in user code is refused with `E1511`.

## Cause

A generic trait is a family of traits — one per argument tuple — and that
family is what the coherence rules keep one-impl-per-pair over. The language
cap closes that question for user code in 1.0: a user trait is a fixed,
concrete set of requirements. The iterator protocol needs the one generic
form, so it lives in the standard library, where the declaration is allowed
only in `iter.ya`.

## Example

```yashy
trait Pair[T] { fn first(self) -> T; }
```

```text
main.ya:1:13
error[E1511]: `Pair` is a generic trait: type parameters on traits are reserved
for the standard library's iterator protocol (`iter.ya`)
trait Pair[T] { fn first(self) -> T; }
            ^^^
  docs: https://yashy.dev/errors/E1511
```

## Fix

Write a concrete trait (`trait First { fn first(self) -> int; }`) and use a
generic function when the type really varies:
`fn first[T](P p) -> T { ... }`.
