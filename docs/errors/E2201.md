# E2201 — target C toolchain missing

A cross build needs the C compiler and linker for the target it names. Yashy's
runtime is C, and the program is linked by `clang`; the compiler does not
bundle a linker, and pretending it did is how a cross build silently links the
host's runtime into a binary that then cannot start on the target.

## Cause

`--target` selects a triple, and the driver asks the toolchain whether it can
build and link a trivial program for that triple. The probe links rather than
only assembling, because `clang --target=<triple>` can emit an object for any
architecture it was built with and still fail at the link for want of the
target's C library. When the probe fails, the build stops with this code and
names the program it looked for.

## Example

```text
$ yashy build --target aarch64-apple-darwin main.ya
error[E2201]: the C toolchain for `aarch64-apple-darwin` is not installed: `clang --target=aarch64-apple-darwin` could not link a trivial program
ld64.lld: error: library not found for -lSystem
clang: error: linker command failed with exit code 1
  looked for `C:\Program Files\LLVM\bin\clang.exe`
  docs: https://yashy.dev/errors/E2201
```

The compiler's own words are quoted rather than paraphrased, because the
toolchain's message is the one that names the missing piece.

## Fix

Install the toolchain for the target, or build for the host:

```text
$ yashy build main.ya
```

`yashy doctor --target <triple>` prints the same answer as a check, so a CI job
can fail early with one line instead of a link error at the end.
