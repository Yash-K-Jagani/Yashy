# E2200 — unsupported target

`--target` names the platform a build is for. The set of triples the compiler
emits for is closed and printed in the diagnostic: `x86_64` and `aarch64` for
`pc-windows-msvc`, `unknown-linux-gnu` and `apple-darwin`. A triple outside
that list is refused before any work starts, rather than half-built and linked
against the wrong runtime.

## Cause

The backend emits textual LLVM IR with a `target triple` and a `target
datalayout` in its header, and the runtime shim is compiled by `clang` with the
same triple. A triple the compiler has no layout or toolchain story for would
produce IR for one platform and a runtime for another, so it is reported at the
flag instead.

## Example

```text
$ yashy build --target riscv64gc-unknown-linux-gnu main.ya
error[E2200]: unsupported target `riscv64gc-unknown-linux-gnu`; supported targets: x86_64-pc-windows-msvc, aarch64-pc-windows-msvc, x86_64-unknown-linux-gnu, aarch64-unknown-linux-gnu, x86_64-apple-darwin, aarch64-apple-darwin
  docs: https://yashy.dev/errors/E2200
```

## Fix

Name a supported triple, or omit `--target` to build for the host:

```text
$ yashy build --target aarch64-apple-darwin main.ya
```

`yashy doctor --target <triple>` reports whether the C toolchain for that
target is installed before a build needs it.
