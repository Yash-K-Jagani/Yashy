# E0109 — the type is written before the name

A declaration writes its type first, then the name: `let int x = 5;`,
`fn add(int a, int b) -> int`. The old order, `let x: int = 5;`, is not a second
spelling — it is this diagnostic.

## Cause

Yashy has one order for the two places a new name is introduced:

- a binding: `let`/`const`, then the type, then the name, then `=`;
- a parameter: the type, then the name.

The type may be omitted on a binding when the initialiser makes it obvious
(`let x = 5;`), but it may never follow the name. A field, an enum payload and a
function type keep `name: type`, because those are a field list and a type, not
a variable declaration: `struct Point { x: int }` and `fn(int) -> int` are
unchanged.

The three ways to get this code:

- `let x: int = 5;` or `const x: int = 5;`;
- a function or method parameter written `a: int`;
- a lambda parameter written `|x: int|`.

`self: *mut T` is a receiver, not a named parameter, and is unchanged.

## Example

```yashy
fn add(int a) -> int {
    let x: int = a + 1;
    return x;
}
```

```text
decl.ya:2:10
error[E0109]: the type is written before the name: write `int x`, not `x: int`
    let x: int = a + 1;
         ^
  docs: https://yashy.dev/errors/E0109
```

## Fix

Move the type in front of the name:

```yashy
fn add(int a) -> int {
    let int x = a + 1;
    return x;
}
```

The same move applies to parameters: `fn add(a: int)` becomes
`fn add(int a)`, and `|x: int|` becomes `|int x|`.
