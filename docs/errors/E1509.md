# E1509 — wrong number of type arguments

A generic type names how many type arguments it takes. Writing a different
number — too many, too few, or none where some are required — is `E1509`,
naming the declared arity and the arity given.

## Cause

`Pair[T]` declares one parameter, so `Pair` alone is missing its argument
and `Pair[i64, i64]` gives two where one was declared. A name that is not
generic at all (`Point[i64]`) has a declared arity of zero. All three are
`E1509`, because the count is what is wrong, not the names inside the
brackets.

## Example

```yashy
struct Pair[T] { first: T, second: T }

fn f(p: Pair[i64, string]) -> int { return 0; }
```

```text
main.ya:3:11
error[E1509]: `Pair` declares 1 type parameter, but `Pair[i64, string]` gives 2
fn f(p: Pair[i64, string]) -> int { return 0; }
          ^^^^^^^^^^^^^^^^^^^
  docs: https://yashy.dev/errors/E1509
```

## Fix

Write as many type arguments as the declaration has, in its order:
`Pair[i64]`, `Entry[string, i64]`. A name that is not generic takes none.
