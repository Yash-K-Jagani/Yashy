# E0607 — misaligned packed field

A field of a `repr(packed)` struct would sit at a byte offset its type's
alignment does not allow.

## Cause

`repr(packed)` asks for a struct with no padding between fields: each field
starts immediately after the one before it. That is a promise about bytes, so
a field whose type needs alignment greater than one has to land on an address
that satisfies it. When it does not, reading or writing the field would be an
unaligned access, which Yashy does not emit silently.

A packed struct whose fields all happen to be naturally aligned still checks:
two `int` fields start at offsets 0 and 8, so packing changes nothing. A
one-byte field in front of an `int` moves that `int` to offset 1, which is the
case this rule refuses.

## Example

```yashy
repr(packed) struct Packet {
    tag: u8,
    value: int,
}
```

```text
packet.ya:3:5
error[E0607]: `repr(packed)` places field `value` at byte offset 1, but `int` needs alignment 8
    value: int,
    ^^^^^
  docs: https://yashy.dev/errors/E0607
```

## Fix

Move the byte-sized fields after the aligned ones, so every field still lands
where its type requires:

```yashy
repr(packed) struct Packet {
    value: int,
    tag: u8,
}
```

If the fields cannot be reordered, drop `repr(packed)` and let the compiler
insert the padding the layout requires.
