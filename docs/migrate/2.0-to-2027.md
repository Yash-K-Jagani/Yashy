# Migrating from 2.0 to 2027

The 2027 edition changes the manifest key, not the language's spelling. A
program that checks under 2.0 checks under 2027 unchanged.

## The edition key

```toml
[package]
name = "demo"
version = "0.1.0"
edition = "2027"
```

`yashyc migrate` rewrites only that key; `--dry-run` prints the diff. The
closed set is `2021` (the 1.0 default) and `2027`; an unknown value is a
diagnostic naming the valid set.

## Ownership stays explicit

A linear value is moved or released explicitly; `defer` releases at scope
exit.

```yashy
fn use_buffer() {
    let *mut int buffer = alloc(8);
    buffer[0] = 7;
    print(buffer[0]);
    buffer.free();
}

fn main() {
    use_buffer();
}
```

## No compiler change to the declaration grammar

The type-first spelling, irrefutable binding patterns and value-based errors
from 2.0 remain the only spellings in 2027:

```yashy
struct Pair { left: int, right: int }

fn main() {
    let Pair pair = Pair { left: 1, right: 2 };
    const Option[int] maybe = None;
    print("${pair.left} ${pair.right}");
    if let Some(value) = maybe {
        print(value);
    }
}
```

## Check the migration

Run `yashyc check`, `yashyc test` and `yashyc verify` after `yashyc migrate`.
The compiler reads both editions from the same manifest table, so a project
can migrate one package at a time in a workspace.
