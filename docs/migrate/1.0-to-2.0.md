# Migrating from 1.0 to 2.0

2.0 keeps 1.0's declaration order and type-first spelling. Most programs need
no change. The changes below are the ones a 1.0 program might hit.

## Declarations keep the type first

The name-first spelling is an error (E0109), not a second form.

```yashy
fn main() {
    let int x = 5;
    const string name = "yashy";
    print("${name} ${x}");
}
```

A struct field and a function *type* keep the colon:

```yashy
struct Point { x: int, y: int }

fn apply(int value, fn(int) -> int f) -> int {
    return f(value);
}

fn main() {
    print(apply(3, |int n| -> int { return n + 1; }));
}
```

## Patterns in bindings are irrefutable

A refutable pattern in `let`, `const` or `for` is E0100; use `switch` instead.

```yashy
fn label(Option[int] value) -> string {
    return switch value {
        case Some(n) { "some" }
        case None { "none" }
    };
}

fn main() {
    print(label(Some(1)));
}
```

## Errors are values

`read_file` and `getenv` answer `Result`/`Option`; no sentinel means failure.

```yashy
fn main() {
    const Option[string] maybe = getenv("YASHY_MIGRATION_SAMPLE");
    print(switch maybe {
        case Some(value) { value }
        case None { "unset" }
    });
}
```

## Check the migration

`yashyc migrate --dry-run <yashy.toml>` prints the `edition` key it would
rewrite without touching the file. The claims in this page are about source
spellings, not about the `edition` key; a project that writes
`edition = "2021"` keeps its 1.0 behaviour until it runs `yashyc migrate`.
